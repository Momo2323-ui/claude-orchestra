# Claude Orchestra — Full System Audit (2026-06)

Scope: every feature, structure, hook, rule, cron surface, ranking mechanism, and search path in
the repo as of `637344d`, plus the live ecosystem it orchestrates (skills, agents, plugins, MCP
servers, connectors). This audit drove the v2 ("score engine") release shipped alongside it.

---

## 1. What v1 was

| Component | What it did | Verdict |
|---|---|---|
| `orchestra-system.md` (constitution) | 20 themed orchestras + NEXUS, 10 fields each, loaded every session | ✅ Strong taxonomy, weak scaling |
| `hooks/orchestra-route.sh` | UserPromptSubmit hook injecting a **static** routing directive | ⚠️ Deterministic *trigger*, zero deterministic *logic* |
| `skills/orchestra-router` | LLM matches intent against a markdown trigger table | ⚠️ Pure prompt engineering — recall depends on the model noticing |
| `skills/orchestra-intake` | Security-scan → classify → file new installs | ✅ Best-in-class doctrine (incl. bulk-install fixture check) |
| `install.sh` | Idempotent, jq-merge, auto-backup, no network/sudo | ✅ Genuinely trustworthy |
| `SECURITY.md`, shellcheck CI (pinned SHAs) | Trust posture | ✅ Ahead of most OSS peers |

## 2. Findings — what was broken or missing

**F1 — The hook never read the prompt (critical).** Claude Code passes the user prompt to
UserPromptSubmit hooks as JSON on stdin; v1 ignored it and printed the same boilerplate every
turn. All real routing was delegated to the LLM's attention. This is the root cause of
"why did THAT skill fire?" surviving v1.

**F2 — Nothing addressed the "your skills are too much" warning (critical).** Claude Code has a
character budget for skill discovery; past it, skill descriptions get truncated and selection
silently degrades ("1% searching is not picking all"). v1 organized *names* of skills in markdown
but left every skill in the autoload path. Organization without budget management doesn't fix
truncation.

**F3 — No machine-readable inventory.** The constitution was prose. Nothing could script against
the roster: no search index, no rankings, no health checks, no dedupe of trigger collisions.

**F4 — No vector/semantic search.** Keyword triggers only. "my checkout flow feels clunky"
matches no trigger but is obviously DESIGN+GROWTH. Paraphrase = routing miss.

**F5 — No ranking or telemetry.** Zero data on which of the hundreds of installed tools actually
fire, which are dead weight, and which deserve first-chair status. Rosters were vibes-based.

**F6 — No scheduled upkeep.** No cron surface, no staleness detection. The system only got
attention when something visibly broke.

**F7 — No reasoning-power policy.** Deep-reasoning keywords (`ultrathink`, `ultraplan`,
`ultracode`, `ultrareview`) and the `/pressure-test` adversarial gate existed in the ecosystem
but nothing routed them: a board-deck question and a typo fix got the same reasoning depth.

**F8 — Announcement noise.** Announce-everything on trivial prompts adds tokens without value
(flagged in the v2 design soak as "announce non-obvious only").

**F9 — Conductor-order hazard in compound routes** (found while building v2): with no defined
ordering, the announced lead could differ from the top-ranked orchestra's conductor.

## 3. What v2 ships (mapping fixes to findings)

| Fix | Component | Findings closed |
|---|---|---|
| Prompt-aware routing hook: stdin → `orchestra route` → injects ONLY the matched slice (orchestras, conductors, pre-ranked players, gates, reasoning keyword, confidence) | `hooks/orchestra-route.sh` + `bin/orchestra route` | F1, F8, F9 |
| Machine registry: triggers, rosters, tiers, gates, reasoning keywords, budget | `~/.claude/orchestra/registry.json` (template + filled example) | F3 |
| Hybrid retrieval: word-boundary trigger scoring + optional **qmd** (BM25 + vector + rerank) boost, graceful fallback, latency opt-in for the hook path (`orchestra qmd on`) | `bin/orchestra route` | F4 |
| Budget doctor + bench: measures skill-description chars vs budget; `orchestra bench` moves cold skills out of the autoload path while keeping them indexed + invocable by path | `bin/orchestra doctor/bench/promote` | **F2** |
| Telemetry → ranking board: PostToolUse hook logs real skill/agent usage (local-only JSONL); `orchestra board` scores tier + usage + recency into S/A/B/C classes | `hooks/orchestra-telemetry.sh` + `bin/orchestra board` | F5 |
| Upkeep: `orchestra upkeep` (index+doctor+board), `orchestra cron` prints the crontab line; cloud equivalent `/loop 24h "run orchestra upkeep"` | `bin/orchestra` | F6 |
| Reasoning escalation doctrine: per-orchestra `reasoning` keyword injected by the route; stacked routes auto-escalate to `ultrathink`; ㉑ AUDIT orchestra makes `/pressure-test` the universal high-stakes gate (SHIP / FIX-FIRST / STOP, opt-in fix loop ≤3) | registry + constitution + router skill | F7 |

## 4. How the v2 pipeline routes a prompt

```
prompt ──► UserPromptSubmit hook (reads stdin JSON)
              └─► orchestra route --hook "<prompt>"
                    ├─ registry trigger scoring (word-boundary, phrase-weighted)
                    ├─ + qmd hybrid search boost (if installed & enabled)
                    ├─ NEXUS override · confidence high/medium/low
                    └─► <orchestra-routing> block: stack · conductors · players
                        · reasoning keyword · gates · announce line
          ──► model activates, announces once, conductor sequences players
          ──► PostToolUse telemetry logs what actually fired
          ──► weekly upkeep re-ranks the board from that telemetry
```

The LLM keeps override authority (sarcasm, novel phrasing), but the default path is now
deterministic, scored, and explainable — and low-confidence routes ask instead of guessing.

## 5. Residual risks / explicit non-goals

- **Trigger lists are still curated.** qmd closes most of the paraphrase gap, but trigger
  hygiene (via `orchestra doctor` collision checks) remains a weekly-upkeep job.
- **Telemetry needs volume.** The board is tier-only until a week or two of real usage accrues.
- **qmd is optional by design.** The engine must never make a prompt fail or stall; hard
  dependency on a bun-installed binary would break the "jq is the only dependency" trust story.
- **Ultra keywords are harness-dependent.** On harnesses that don't recognize them they read as
  plain words — harmless, documented in the constitution.
- Still no bundled third-party skills (org-layer doctrine unchanged), still Bash+Markdown only.

## 6. Bottom line

v1 was a well-built *convention*. v2 is a *system*: deterministic retrieval feeding the model,
a budget mechanism that actually fixes skill-discovery truncation, usage-ranked rosters, and a
reasoning/audit policy wired to the places that need it. The constitution stays human-readable;
the registry makes it executable.
